# EZ SVN 사용 설명서

작성 기준: 2026-10-19 현재 소스

EZ SVN은 SVN 작업 폴더의 변경 사항을 확인하고, AI 검수 결과를 검토한 뒤 커밋할 수 있는 Windows 프로그램입니다. 이 설명서는 현재 구현된 화면과 동작을 기준으로 작성했습니다.

## 1. 시작하기

### 실행 준비

- Windows와 .NET Framework 4.8이 필요합니다. 프로그램은 x86으로 실행됩니다.
- 배포받은 폴더를 유지한 상태로 `SvnAiClient.exe`를 실행합니다. 창 제목은 **EZ SVN**입니다.
- EXE만 따로 옮기지 마세요. 같은 폴더의 DLL, 실행 설정 파일과 하위 폴더를 함께 배포해야 합니다.
- 프로그램에 사용하는 SUIT·D2Coding 글꼴은 포함된 리소스를 통해 적용됩니다. 별도 글꼴 설치는 필요하지 않습니다.

### 작업 폴더 준비

EZ SVN에는 **이미 체크아웃된 SVN 작업 폴더**를 등록합니다. 등록 기능은 저장소를 새로 체크아웃하거나 일반 폴더를 SVN 작업 폴더로 바꾸는 기능이 아닙니다.

작업 폴더가 없다면 먼저 사용 중인 SVN 도구로 체크아웃하세요. 저장소 조회·최신 버전 받기·커밋에는 저장소 연결과 해당 작업에 필요한 권한이 있어야 합니다.

### 처음 사용하는 순서

1. **작업 폴더 등록…**으로 기존 작업 폴더를 등록합니다.
2. 상단 목록에서 작업 폴더를 선택합니다.
3. **설정**에서 사용할 AI 제공자와 모델을 설정하고 저장합니다.
4. 변경한 파일의 **커밋** 체크박스를 선택합니다.
5. **검수 및 커밋…**에서 변경 내용을 확인하고 AI 검수를 실행합니다.
6. 결과와 최종 메시지를 검토한 뒤 **커밋 실행**을 누릅니다.

## 2. 작업 폴더 등록과 관리

### 등록

상단 **작업 폴더 등록…**을 누르고 다음 항목을 입력합니다.

| 항목 | 입력 내용 |
|---|---|
| 로컬 경로 | SVN 작업 폴더의 경로. **찾아보기**로 선택할 수 있습니다. |
| 표시 이름 | 목록과 폴더 트리에 표시할 이름. 비워두면 폴더 이름을 사용합니다. |
| 사용자명 | 해당 저장소에 사용할 SVN 인증 사용자명 |
| 비밀번호 | SVN 인증 비밀번호 |

**등록**을 누르면 작업 폴더 목록에 추가되고 상태 조회를 시작합니다.

### 수정과 제거

**설정 → 작업 폴더**에서 등록한 항목을 선택한 뒤 **추가·수정·제거**를 사용할 수 있습니다.

- 기존 항목을 수정할 때 비밀번호를 비워두면 저장된 비밀번호를 유지합니다.
- 목록에서 제거해도 실제 폴더나 저장소의 파일은 삭제되지 않습니다.
- 메인 화면의 폴더 트리 우클릭 메뉴에서도 등록과 목록 제거 명령을 사용할 수 있습니다.

## 3. 메인 화면 사용하기

### 화면 구성

| 영역 | 용도 |
|---|---|
| 상단 작업 폴더 목록 | 현재 관리할 작업 폴더 선택 |
| 작업 폴더 전체 명령 | 상태 새로고침, 최신 버전 받기 |
| 왼쪽 폴더 탐색 | 작업 폴더 안의 폴더 이동 |
| 현재 위치와 파일 목록 | 탐색 중인 경로, 파일 상태, 검색과 필터 |
| 하단 커밋 대상 | 체크한 파일을 모아서 확인하고 커밋 창 열기 |
| 하단 상태 표시줄 | 작업 진행, AI 제공자, 저장소 주소 확인 |

### 행 선택과 커밋 체크의 차이

두 선택 방식은 서로 다른 용도로 사용합니다.

| 선택 방식 | 적용되는 작업 |
|---|---|
| 파일 행 클릭, Ctrl·Shift를 이용한 다중 선택 | 선택 파일 되돌리기, SVN 추가·삭제 예약 등의 파일 작업 |
| 파일의 **커밋** 체크박스 | 하단 커밋 대상에 포함 |
| 파일 우클릭 후 **이 파일의 이력 보기** | 여러 행을 선택했더라도 우클릭한 파일 하나의 로그 조회 |

파일 행을 선택하는 것만으로 커밋 대상에 추가되지는 않습니다. 커밋할 파일은 체크박스로 선택하세요. 다른 폴더로 이동해도 체크한 대상은 하단 목록에서 확인할 수 있습니다.

### 검색과 필터

- 검색란에서 **현재 표시된 목록의 파일명 또는 경로**를 검색할 수 있습니다.
- **변경 항목만**을 선택하면 변경된 파일과 하위에 변경 사항이 있는 폴더를 중심으로 표시합니다.
- **하위 폴더 포함**은 변경 항목 필터를 켠 상태에서 사용할 수 있습니다.
- 미등록 빌드 출력물은 `bin`, `obj`, `classes`, `target`, `build`, `out` 등의 폴더에서 숨깁니다. 해당 경로에 있더라도 SVN 관리 항목과 접근에 필요한 부모 폴더는 유지합니다.

### 커밋 대상에서 제외

하단 목록에서 파일을 선택하고 **커밋 대상에서 제외**를 누릅니다. 커밋 대상에서만 빠지며, 파일을 삭제하거나 변경 내용을 되돌리지는 않습니다.

## 4. 변경 내용 확인과 SVN 작업

### 상태 새로고침과 최신 버전 받기

| 명령 | 동작 |
|---|---|
| 상태 새로고침 | 선택한 작업 폴더 전체의 SVN 상태를 다시 조회합니다. |
| 최신 버전 받기 | 저장소의 최신 변경 사항을 선택한 작업 폴더 전체에 반영합니다. |

두 명령의 대상은 **선택한 작업 폴더 전체**입니다. 현재 탐색 중인 하위 폴더나 커밋 체크 여부로 범위가 제한되지 않습니다.

### 변경 내용 보기

메인 파일 목록에서 파일을 더블클릭하거나, 우클릭 후 **변경 내용 보기**를 선택합니다. 현재 작업 파일과 SVN BASE의 차이를 변경 비교 화면에서 확인할 수 있습니다.

미등록 파일은 먼저 **SVN 추가**를 실행해야 합니다. 누락 파일은 삭제 예약 또는 되돌리기로 상태를 정리한 뒤 비교하세요.

### SVN 추가

1. 존재하는 미등록 파일의 행을 선택합니다.
2. 우클릭 후 **SVN 추가**를 선택합니다.
3. 추가 예약된 파일을 커밋 대상으로 체크합니다.

추가는 SVN 관리 대상으로 예약하는 작업입니다. 저장소에 반영하려면 커밋해야 합니다. 파일 작업은 파일 단위이며, 미등록 상위 폴더가 필요한 경우 먼저 다른 SVN 도구에서 폴더 상태를 정리해야 할 수 있습니다.

### SVN 삭제 예약

1. 삭제할 파일의 행을 선택합니다.
2. 우클릭 후 **SVN 삭제 예약 (로컬 파일 유지)**를 선택합니다.
3. 확인 창에서 대상 파일을 확인합니다.
4. 삭제 예약된 파일을 체크하고 커밋합니다.

이 명령은 **로컬 파일을 유지하면서 저장소 삭제를 예약**합니다. 저장소에서 실제로 삭제되는 시점은 커밋 성공 후입니다.

### 선택 파일 되돌리기

되돌릴 파일의 행을 선택한 뒤 **선택 파일 되돌리기…**를 누릅니다. 확인한 파일의 로컬 변경이나 추가·삭제 예약을 되돌립니다. 로컬 수정 내용이 사라질 수 있으므로 확인 창의 대상을 확인하세요.

되돌리기의 대상은 **행으로 선택한 파일**이며, 커밋 체크 목록과 다를 수 있습니다.

## 5. AI 검수 설정

상단 **설정 → AI 검수 설정**에서 연결과 검수 옵션을 지정합니다.

### 기본 제공자와 편집 중인 탭

- **기본 검수 프로바이더**는 새 커밋 창에서 기본 선택할 AI 제공자입니다.
- 아래의 OpenAI·Claude·Gemini·Local 탭은 해당 제공자의 설정을 편집하는 곳입니다.
- 설정 탭을 전환하는 것만으로 기본 제공자가 바뀌지는 않습니다. 화면의 **편집 / 기본 검수** 표시를 확인하세요.

### 기본 설정

| 항목 | 설명 |
|---|---|
| API 키 | OpenAI·Claude·Gemini의 서비스 인증 키 |
| 모델 | 해당 계정이나 서버에서 사용할 수 있는 모델 ID |
| 서버 주소 | Local에서 사용할 OpenAI 호환 서버의 기본 주소 |
| 권장 모델 적용 | 편집 중인 제공자에 권장 모델과 관련 프리셋 적용 |

모델은 목록에서 선택하거나 직접 입력할 수 있습니다. 실제 사용 가능한 모델은 사용하는 계정과 서버 환경에 따라 확인해야 합니다.

Local의 서버 주소는 예를 들어 `http://localhost:11434`처럼 기본 주소로 입력합니다. 프로그램이 뒤에 `/v1/chat/completions`를 붙여 요청하므로 해당 경로를 중복 입력하지 마세요.

### 고급 설정

**고급 설정 펼치기**를 누르면 토큰 한도와 추가 실행 옵션이 표시됩니다.

- **입력 토큰 한도:** 검수 요청 전에 추정 입력 크기를 검사하는 기준입니다.
- **출력 토큰 한도:** AI 응답의 최대 생성 토큰 설정입니다.
- **요청 제한 시간·추론 강도:** OpenAI 탭에서 조정할 수 있습니다.

고급 설정을 접어도 입력값은 유지되며 저장에도 반영됩니다. 권장 모델 적용 시 관련 한도가 바뀔 수 있으므로 필요한 경우 고급 설정에서 확인하세요.

### 검수 항목과 자동 검수

검수 항목에서 버그·논리 오류, 보안, 가독성, 디버그 코드, 변경 요약 등의 요청 기준을 선택합니다.

**커밋 전 AI 검수를 자동으로 실행**을 켜면, 유효한 검수 결과가 없을 때 커밋 버튼이 먼저 검수를 실행합니다. 텍스트 대상의 검수가 실패하거나 부분 완료되면 원인을 해결하고 다시 검수해야 합니다. 이 옵션을 끄면 수동 검수와 직접 작성한 메시지로 커밋할 수 있습니다.

설정 변경을 적용하려면 **저장**을 누릅니다. **취소**하면 편집 내용을 적용하지 않습니다.

## 6. AI 검수와 커밋

### 1단계: 커밋 대상 확인

메인 화면에서 파일을 체크하고 **검수 및 커밋…**을 누릅니다.

- 커밋 창에서도 파일별 체크를 변경할 수 있습니다.
- **커밋** 열 제목을 클릭하면 전체 선택을 전환합니다.
- 파일 목록 아래 경계를 드래그해 목록 높이를 조절할 수 있습니다.
- 파일을 선택한 뒤 **최신 버전과 비교**를 누르거나, 파일 행을 더블클릭해 HEAD와 작업 파일을 비교합니다. 체크박스 셀의 더블클릭은 비교 진입에서 제외됩니다.

### 비교 기준 이해하기

| 위치 | 원본과 비교 대상 |
|---|---|
| 메인 화면의 변경 내용 보기 | SVN BASE → 현재 작업 파일 |
| AI 검수 | SVN BASE와 현재 작업 파일의 전체 소스 및 Diff |
| 커밋 창의 최신 버전과 비교 | 저장소 최신 HEAD → 현재 작업 파일 |
| SVN 로그의 두 리비전 비교 | 선택한 과거 리비전 → 선택한 최근 리비전 |

**BASE**는 작업 폴더가 기준으로 삼는 저장소 버전이고, **HEAD**는 조회 시점의 저장소 최신 버전입니다. 작업 폴더가 최신이 아니면 두 비교 결과는 다를 수 있습니다. HEAD 비교는 조회 기능이므로 작업 파일을 업데이트하거나 AI 검수 기준을 HEAD로 바꾸지는 않습니다.

### 2단계: 변경 배경 입력

**변경 배경 펼치기**를 눌러 변경 목적과 검수 요청을 입력합니다. 예를 들어 다음처럼 작성할 수 있습니다.

> 설정 저장 실패 시 기존 설정을 유지하도록 수정했습니다. 오류 발생 후에도 이전 설정으로 계속 작업할 수 있는지 확인해주세요.

입력란을 접어도 내용은 유지되고 검수 요청에 포함됩니다. 접힌 상태에서는 첫 줄 요약을 확인할 수 있습니다.

### 3단계: AI 검수 실행

제공자를 선택하고 **AI 검수 실행**을 누릅니다. 텍스트 파일의 변경 전후 전체 소스, Diff와 입력한 변경 배경을 선택한 AI 제공자에게 전달합니다. 클라우드 제공자를 사용하면 이 내용이 해당 외부 서비스로 전송됩니다.

검수는 변경으로 생기거나 악화된 문제를 중심으로 요청합니다. 기존 문제는 핵심 기능 불능·심각한 데이터 손상 등 치명적인 경우에 한해 보고하도록 구성되어 있습니다.

입력 한도를 초과하면 일부 소스만 잘라 보내지 않고 요청을 중단합니다. 이때는 검수·커밋 대상을 작은 작업 단위로 나누어 각각 진행하거나, 사용할 모델의 한도 안에서 설정을 조정하세요.

### 텍스트와 바이너리의 처리

- 텍스트 파일은 AI 검수에 전달합니다. 코드 외에 JSON·XML·설정 파일도 텍스트로 읽을 수 있으면 대상이 됩니다.
- 바이너리 또는 지원하지 않는 인코딩의 파일은 AI 검수에서 제외하며, 혼합 검수 결과에 제외 개수를 표시합니다.
- 커밋 승인과 실행 전에는 파일 내용의 SHA-256, 존재 여부, SVN 상태와 속성 Diff를 확인합니다.
- 삭제 예약 파일은 로컬에 남은 파일의 내용 해시 대신 삭제 예약 상태 등을 확인합니다.
- 바이너리만 선택해도 커밋할 수 있습니다. 이 경우 AI 성공 결과를 만들지 않으며 AI 검수 이력도 생성하지 않습니다. 상태 확인 후 다시 커밋하라는 흐름이면 확인한 뒤 **커밋 실행**을 다시 누릅니다.

### 4단계: 결과와 이슈 확인

| 표시 | 확인할 내용 |
|---|---|
| 요약 | 검수 상태, 주요 결과, 추정·실제 토큰 사용량과 소요 시간 |
| 이슈 | 오류·경고·참고 항목, 파일 위치, 설명 |
| 오류 상세 | 검수 실패 등의 오류 설명. 해당 내용이 있을 때 표시됩니다. |

이슈를 선택하고 **선택 이슈 Diff 보기**를 누르거나 이슈를 더블클릭하면 **검수 당시**의 변경 내용을 확인합니다. 행 위치 정보가 있으면 해당 위치로 이동합니다.

AI 검수 결과는 개발자가 확인해야 합니다. 오류 이슈가 있으면 커밋 전 추가 확인 창이 표시됩니다.

### 5단계: 최종 커밋 메시지 작성

최종 메시지를 직접 입력하거나 **AI 제안 보기 → 커밋 메시지에 적용**을 사용합니다. 제안을 적용하면 현재 최종 메시지가 제안 내용으로 바뀌므로 기존에 작성한 내용이 있다면 확인하세요.

AI 제안을 접으면 최종 메시지를 전체 폭으로 작성할 수 있습니다. 펼치면 최종 메시지와 제안을 나란히 확인할 수 있습니다.

### 6단계: 커밋 실행

1. 대상 파일, 결과와 최종 메시지를 확인합니다.
2. **커밋 실행**을 누릅니다.
3. 자동 검수가 먼저 수행된 경우 결과를 확인한 후 다시 **커밋 실행**을 누릅니다.
4. 성공 안내의 SVN 리비전을 확인합니다.

검수 후 대상 파일·제공자·변경 배경·파일 내용이 달라지면 기존 결과를 무효화하고 재확인을 요구합니다. 커밋 직전 승인 정보와 현재 파일 상태가 달라져도 작업을 중단합니다.

커밋이 성공하면 유효한 AI 검수 이력이 있는 경우 해당 이력에 SVN 리비전을 연결합니다. 이력 저장이나 리비전 연결이 실패해도 이미 성공한 SVN 커밋을 실패로 처리하지 않습니다.

## 7. SVN 로그와 리비전 비교

### 폴더별 이력

메인 화면에서 폴더를 탐색한 뒤 경로 오른쪽의 **현재 폴더 이력**을 누릅니다. 현재 보고 있는 폴더 범위의 로그를 조회합니다.

### 파일별 이력

파일 목록에서 원하는 파일을 우클릭하고 **이 파일의 이력 보기**를 선택합니다. 여러 파일을 선택한 상태에서도 우클릭한 파일 하나의 로그를 조회합니다.

### 로그 화면 사용

- 조회 건수를 지정하고 **새로고침**으로 다시 조회합니다.
- 작성자·메시지 등의 열 아래 필터 행으로 조회된 목록을 검색합니다.
- **조회 중단**은 진행 중인 조회의 취소를 요청합니다.
- 리비전을 선택하면 메시지와 변경 경로를 확인할 수 있습니다.

### 한 리비전의 변경 보기

리비전을 더블클릭하면 직전 시점과 해당 리비전 사이의 변경을 조회하고 첫 번째 변경 파일의 비교 화면을 엽니다. 다른 파일은 변경 경로 목록에서 선택하고 **변경 내용 보기**를 누르거나 더블클릭합니다.

폴더 변경만 있는 경우에는 파일 비교 화면을 열지 않습니다.

### 두 리비전 비교

1. Ctrl+클릭으로 서로 다른 리비전 두 개를 선택합니다.
2. **비교할 범위**의 리비전 순서를 확인합니다.
3. **선택한 두 시점 비교**를 누릅니다.
4. **표시 범위**에서 실제 적용된 비교 범위와 변경 건수를 확인합니다.
5. 변경 경로에서 원하는 파일의 변경 내용을 엽니다.

비교는 오래된 리비전에서 최근 리비전으로 진행합니다. 예를 들어 r100과 r120을 선택하면 두 시점의 파일 상태를 비교하며, r100 커밋과 r120 커밋의 수정 목록만 따로 대조하는 방식은 아닙니다.

## 8. AI 검수 이력 조회

상단 **AI 검수 이력**을 누릅니다.

- **현재 작업 폴더만**을 선택하면 해당 작업 폴더의 이력으로 제한합니다.
- 선택을 해제하면 로컬에 저장된 전체 이력을 조회합니다.
- 목록의 필터 행으로 조회된 이력을 검색할 수 있습니다.
- 이력을 선택하면 검수 상태, 연결 리비전, 제공자·모델과 토큰 정보를 확인합니다.

기본 상세 탭은 **요약·이슈·대상 파일**입니다. **추가 정보 보기**를 누르면 **변경 배경·제안 메시지·전체 기록**도 표시합니다. 조회 오류가 있으면 추가 정보 표시 여부와 관계없이 **조회 오류** 탭이 나타납니다.

검수 이력은 성공·실패·취소·부분 완료 상태를 구분합니다. **과거 이력은 조회 전용이며 현재 변경 내용의 검수 완료 상태로 재사용되지 않습니다.**

### SVN 이력과의 관계

AI 검수 이력과 SVN 커밋 이력은 1:1 관계가 아닙니다.

- 같은 변경을 여러 번 검수하고 한 번만 커밋할 수 있습니다.
- 검수 후 커밋하지 않을 수 있습니다.
- AI 검수 없이 커밋하거나, 바이너리만 커밋할 수 있습니다.
- 이력 저장 또는 연결 실패로 리비전이 비어 있을 수 있습니다.

따라서 **연결 리비전이 없다는 표시만으로 커밋하지 않았다고 판단하지 마세요.** 실제 커밋 여부는 SVN 로그에서 확인합니다.

## 9. 변경 비교 화면

변경 비교 화면은 파일 경로와 비교 기준을 상단에 표시합니다. 원본·수정본의 기준은 이 화면을 연 기능에 따라 달라지므로 상단 표시를 확인하세요.

| 기능 | 사용 방법 |
|---|---|
| 좌우 비교 | 왼쪽 원본과 오른쪽 수정본의 줄 단위 변경 확인 |
| 이전 변경·다음 변경 | 변경 구간 사이 이동 |
| 범례 보기·접기 | 추가·삭제·수정·정렬 빈 줄의 색상 설명 표시 전환 |
| 변경 내용 원문 | SVN Diff 원문 및 속성 변경 정보 확인 |
| 닫기 | 비교 화면을 닫고 이전 화면으로 복귀 |

바이너리나 속성 변경처럼 좌우 텍스트 비교가 없는 경우에는 원문 정보와 상태 안내를 확인합니다. 이 화면에서는 소스를 편집하거나 변경을 되돌리지 않습니다.

## 11. 데이터 보관과 문제 해결

### 저장 위치

표시 이름은 EZ SVN이지만 기존 데이터 호환을 위해 저장 폴더 이름은 `SvnAiClient`를 사용합니다.

| 데이터 | 기본 위치 |
|---|---|
| 작업 폴더 및 AI 설정 | `%APPDATA%\SvnAiClient\settings.json` |
| 메인 화면 배치 | `%APPDATA%\SvnAiClient\main-view-layout.json` |
| AI 검수 이력 | `%LOCALAPPDATA%\SvnAiClient\ReviewHistory` |
| 실행 로그 | `NLog.config`에서 지정한 `logs` 경로 |

API 키와 SVN 비밀번호는 Windows 사용자 계정에 연결된 DPAPI로 암호화해 설정에 저장합니다. 다른 PC나 Windows 사용자로 설정 파일만 복사하면 해당 자격 증명을 복호화하지 못할 수 있으므로 다시 입력하세요.

검수 이력에는 시각·제공자·모델·대상 경로·변경 배경·상태·요약·이슈·제안 메시지·토큰 정보와 연결 리비전 등을 기록합니다. API 키·비밀번호·변경 전후 전체 소스·Diff 원문은 이력 저장 항목에 포함하지 않습니다.

### 자주 발생하는 상황

| 상황 | 확인할 내용 |
|---|---|
| 작업 폴더를 등록했지만 조회되지 않음 | 기존 SVN 작업 폴더인지, 경로가 존재하는지, 저장소와 인증에 문제가 없는지 확인합니다. |
| 새 파일이 커밋 대상에 나타나지 않음 | SVN 추가 예약 여부를 확인합니다. 출력물 제외 폴더에 있는 미등록 파일은 숨겨질 수 있습니다. |
| 메인 비교와 최신 버전 비교가 다름 | BASE와 HEAD가 다를 수 있습니다. 최신 버전 받기와 비교 기능의 범위를 구분하세요. |
| 검수 후 다시 검수하라는 안내 | 대상·제공자·변경 배경 또는 실제 변경 내용이 달라졌는지 확인합니다. |
| AI 요청 실패 | 선택한 제공자의 키·모델·연결 상태를 확인하고 오류 상세를 읽습니다. Local은 기본 서버 주소와 모델을 확인합니다. |
| 입력 한도 초과 | 대상을 작은 검수·커밋 단위로 나누거나 모델에 맞는 입력 한도를 설정합니다. |
| 요청 시간 초과 | 제공자 상태와 요청 크기를 확인합니다. OpenAI는 고급 설정에서 제한 시간을 조정할 수 있습니다. |
| AI 제안 버튼이 비활성 | 유효한 성공 결과에 제안 메시지가 있는지, 작업이 진행 중인지 확인합니다. |
| 이력 저장 또는 리비전 연결 실패 | 표시된 안내와 로그를 확인합니다. 커밋 성공 안내가 있었다면 SVN 로그로 완료 여부를 확인합니다. |
| 커밋 취소·연결 오류로 성공 여부가 불명확 | 같은 변경을 다시 커밋하기 전에 SVN 로그에서 실제 완료 리비전을 확인합니다. |
| 커밋 성공 후 상태 갱신 실패 | 성공 안내의 리비전을 확인하고 상태 새로고침을 실행합니다. |

사용 중 문제가 발생하면 수행한 작업, 표시된 오류 문구와 발생 시각을 함께 기록하세요. 로그를 공유할 때는 저장소 주소·파일 경로 등 내부 정보도 포함될 수 있으므로 필요한 범위만 전달합니다.
